# Quickstart: validating the decoder framework

**Feature**: 007-decoder-framework-annotations

How to prove, step by step, that the feature works end to end. Everything runs without hardware. The
test names below are the planned ones (the task list creates them); each scenario names the requirement
it proves. Contracts: [decoder-api](contracts/decoder-api.md), [deco-section](contracts/deco-section.md),
[host-api-1.1](contracts/host-api-1.1.md), [decoder-ui](contracts/decoder-ui.md). Entities and limits:
[data-model](data-model.md).

## Prerequisites

- The pinned toolchain (`rustup` installs it from `rust-toolchain.toml`); the MSRV job builds every crate
  except the application with Rust 1.85.
- Windows 10/11 or Debian 13. A graphics driver and a desktop session are needed only for scenario 8.
- On Debian, `build-essential`, `git` and `curl` (as in CI).

```text
cargo build --workspace
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features
```

## 1. The sample decoder decodes what the generator wrote (SC-006, FR-035 to FR-037)

```text
cargo test -p la-decoders --test round_trip
LA_ROUND_TRIP_SEEDS=10000 cargo test -p la-decoders --release --test round_trip -- --ignored
```

Expected: for every seed the decoded bytes equal the generated bytes; with deliberate errors every planted
incomplete byte is reported at its position and the valid content around it is decoded. The same seed
gives byte-identical signals (a second run is compared).

## 2. Every kind of decoder fault is contained (SC-005, FR-020 to FR-023)

```text
cargo test -p la-decoders --test fault_injection
cargo test -p la-host --test decoder_faults
```

Expected: test decoders that return an error, panic, ignore cancellation, exceed the memory or annotation
budget, and emit invalid annotations, each next to a healthy decoder on the same capture. After each: the
capture is byte-identical, the healthy decoder's results are unchanged, exactly one localized message with
the right `decoder.*` code exists in all six languages, the log has the code and no signal data, and the
partial results are kept and marked incomplete.

## 3. Window queries cost the same on any capture size (SC-002, SC-003, FR-010, FR-027)

```text
cargo test -p la-decoders --test index
cargo test -p la-decoders --test lanes
cargo bench -p la-host --bench annotation_plan
```

Expected: the store agrees with a brute-force reference on random overlapping and nested annotations; a
probe-count test shows the cost of a window query and of the per-column counts independent of the number of
annotations outside the window; a single one-sample annotation among millions is represented at every zoom
level (alone or in a dense mark); the benchmark's plan time for a finished decode of one million and ten
million annotations on a 100-million and a 1,000-million-sample capture does not grow with either (a run fails
if the ten times larger case is more than twice as slow), and stays inside the frame budget.

## 4. Background, cancellable, growing (SC-004, SC-009, FR-012 to FR-017)

```text
cargo test -p la-decoders --test execution
cargo test -p la-host --test decoder_commands
cargo test -p la-app --release -- --ignored measure_decoder
```

Expected: progress is monotonic; Cancel takes effect within one second and keeps results; a decoder follows
a capture that is appended to while it runs and never repeats or loses an annotation; a change of setup
cancels the pass and never mixes old and new results; the longest call of the interface thread during
decoding, cancelling, zooming and a language change on 100 million samples is under 100 ms; at the virtual
device's highest rate the capture loses no more samples with a decoder than without.

## 5. Stacks (FR-018, FR-019)

```text
cargo test -p la-decoders --test stacking
```

Expected: an upper test decoder sees exactly the items of the lower one; a changed, re-run or removed lower
decoder re-runs, marks outdated or removes the upper one; a fault below marks the one above incomplete without
failing it; cycles, mismatched kinds and a chain deeper than 4 are refused with the right codes.

## 6. Saving and opening (SC-008, FR-031 to FR-034)

```text
cargo test -p la-decoders --test deco_section
cargo test -p la-decoders --test dann_section
cargo test -p la-session
cargo test -p la-host --test decoder_sessions
```

Expected: byte vectors written from the contract decode as documented; round trips of an empty, a typical
and a maximal state; every validation rule has a failing fixture; the mutation fuzzer (every single-byte
change, truncation and extension) never panics and any accepted payload re-encodes identically; unknown
decoders and options survive a load and a save byte for byte; files of format 1.0 and 1.1 still open; a
save interrupted at a hundred points leaves the old file intact.

## 7. Random actions (SC-007)

```text
cargo test -p la-host --test random_walk
cargo test -p la-host --release --test random_walk -- --ignored
```

Expected: 100,000 random actions (now including adding, configuring, stacking, cancelling, re-running and
removing decoders, capture growth, saves and opens with damaged decoder sections, language changes) without a
crash, hang, lost capture data or mixed results; two million in the nightly workflow.

## 8. In the window (SC-001, SC-010, SC-011; manual)

```text
cargo run --release -p la-app
```

1. Choose the virtual device, **Start**, and wait for the capture to end.
2. **Decoders → Add decoder…**, choose **Clocked bits**, assign the clock and data channels, **OK**. Within
   seconds the decoder lane shows bytes with their values; zoom in on one byte to see its bits, the arrows on
   the clock edges and the dot on the data channel.
3. Press **Next annotation** a few times; the view follows. Click an annotation and read its details in the
   panel.
4. Set **Signal** to the decoder's generator with deliberate errors, capture again, and find the error marks.
5. Save, close, reopen: the decoder is back and decodes again; with **Save decoded results** on, the lane is
   there at once.
6. Change the language to Japanese and German: all decoder texts change; check the dialog and lane at the
   smallest window size.
7. Let the application sit with decoders finished: the processor use stays under 1 % of one core.

Record each manual step with the platform and date in this feature's `verification.md`.
